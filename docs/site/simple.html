HEXARCH in 10 minutes

Instruction and Data Memory Hierarchy. The whole project on one page, in plain words. Read this first; the full study guide has the detail.

1The idea

A processor needs two things from memory: the next instruction and the data the instruction uses. If both live in one memory with one port, they must take turns. If instructions and data have separate memories (Harvard), both can happen in the same clock cycle. We built both in Verilog, ran the same programs, and counted cycles.

In Phase II we added the shared lower-level memory from the brief: two tiny caches (one for instructions, one for data) sitting on top of one shared memory. This is how real computers do it (a "modified Harvard" machine).

2Three designs, one controller

DesignMemoryCycles for N instructions
HarvardSeparate instruction and data memoryN + 1
SharedOne memory, one portN + 1 + M (M = LOAD/STORE count)
Hierarchy (Phase II)Two small caches over one shared memoryN + 1 + I + D (I, D = cache misses)

The demo program is LOAD 0, STORE 1, HALT (copy one value). Harvard = 4 cycles, Shared = 6, Hierarchy = 6.

3How the cache works (five rules)

  1. Each cache has 2 lines of 4 bytes.
  2. Hit (already in the cache): no delay.
  3. Miss: the controller pauses 1 cycle (hold) while a 4-byte block is copied from the shared memory.
  4. The shared memory has one port: if both caches miss together, data goes first.
  5. STORE writes through to the shared memory (and to the cache if the byte is there). It never happens during a pause.

Why 4 bytes per line? The next instruction is usually the next address, so one miss brings three free hits. A 16-byte program has only 4 instruction misses.

4The 6 cycles of the hierarchy demo

CycleWhat happens
1Pause: fetching LOAD misses the instruction cache; block 0 copied in
2Fetch LOAD (hit)
3Pause: LOAD needs data[0], data cache misses; block copied in
4LOAD runs (reads 7) while STORE is fetched
5STORE runs (writes 7) while HALT is fetched
6HALT runs. Done: 3 + 1 + 1 + 1 = 6

7Ten answers to remember

Why is Harvard faster?Fetch and data access happen in the same cycle. Shared has one port, so each LOAD/STORE blocks the next fetch.
Is it always faster?No. With no LOAD/STORE both take the same time (M = 0).
What is a cache hit and a miss?Hit: the byte is already in the small memory, free. Miss: copy a block from the lower memory, 1 cycle.
Why is the hierarchy not faster than Harvard?Our Harvard model has no miss cost, so the hierarchy can only match it. It models a realistic shared memory and beats shared-only when data and code are reused.
What is the hold signal?An input that freezes the controller for a cycle while a miss is served. It is tied to 0 in Phase I, so Phase I results did not change.
Why is data served before instructions?One port. The LOAD already running is older than the next fetch.
What is write-through?A STORE also goes straight to the lower memory, so memory is always right. Simple, no dirty bits.
How did you test it?Self-checking testbenches: 11 scenarios, 2000 random programs, and 7 + 3000 for the hierarchy, compared with software models; cycle counts follow the formulas every time.
What are the limits?Tiny caches, no branches, simulation only, no synthesis or timing numbers.
Did you use AI?Yes, for starter code and drafts (stated in the report). We reviewed, ran and can explain it.
